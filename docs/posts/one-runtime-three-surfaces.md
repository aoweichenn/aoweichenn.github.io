# 一个运行时，三种入口

<PostMeta date="2026-10-27" :tags="['Nova', '架构']" />

同一个任务可以从网页发起，在终端查看，又被脚本继续处理。如果每个入口都自己解释任务状态，用户看到的进展很快就会不一致。

Nova 的高层设计选择了一个 C++20 核心，围绕会话、Agent 和工具调用定义工作边界。Web、TUI 和 CLI 面向不同的操作方式，但不应各自发明一套任务语义。

## Web：适合观察与整理

网页为会话、文件和工具活动提供更宽的空间。它适合在多条线索之间切换，也适合呈现需要人做决定的步骤。界面可以丰富，但不能用本地显示状态替代运行时的事实。

## TUI：适合保持键盘工作流

终端工作台强调快速阅读、切换和输入。它需要跟随同一份会话状态，才能与网页互相接续。真实终端环境还会带来尺寸变化、输入在途和连接中断等边界，因此 TUI 不只是把网页缩成字符画。

## CLI：适合组合

脚本 CLI 让任务能接入已有命令流程。它需要清楚表达请求是否被接纳、当前是否还在运行，以及退出时究竟发生了什么。对自动化来说，这些结果比一段漂亮输出更重要。

## 同一条线索

这三种入口仍处于原型迭代中。它们的共同目标是让用户无论从哪里进入，都能追溯同一项工作的来路。更简洁的结构图放在 [设计页](/design/)；当前完成范围见 [进展页](/progress/)。
