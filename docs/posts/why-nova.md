# 为什么开始做 Nova

<PostMeta date="2026-10-27" :tags="['Nova', '设计']" />

我在做 Nova，一个用 C++20 写的 Agent 工作台。起初想解决的问题很实际：一段对话里跑了命令、改了文件，页面又断开了。重新打开时，程序得知道哪些步骤已经发生，哪些只是发出了请求。

普通聊天界面很容易把这件事藏起来。最后只留下几段文字，但对开发工具来说，工具调用的结果比文字更要紧。命令有没有执行完？取消是在结果之前还是之后到的？这些都不能靠界面猜。

## 先把状态弄明白

Nova 现在围绕会话、运行记录和工具结果整理代码。Web、TUI 和 CLI 都是入口；真正的状态应该由同一个 Host 管。否则一个入口认为任务完成，另一个入口还在等结果，问题会越来越难查。

这不是说当前实现已经处理好了所有情况。设计文档写了目标，原型里也有能跑的路径，但失败、重启和多端切换还需要继续验证。
