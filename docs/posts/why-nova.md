# 为什么开始做 Nova

<PostMeta date="2026-10-27" :tags="['Nova', '设计']" />

Agent 给出答案很快。但一次真正的工作通常不止有答案：它会读取文件，调用工具，等待人的决定，也可能在进行中被取消或中断。只看最终文字，很难知道哪些动作真的发生了、哪些仍待处理。

Nova 从这个落差开始。它不是要为聊天框换一层外观，而是探索怎样为持续工作建立一个清楚的运行时：任务属于哪个会话，工具结果何时确定，使用者如何看见进展，下一次打开时又该从哪里继续。

## 把过程放回视野

有些操作会改变外部世界。一个命令执行过之后，即使页面断开，结果也不能被当作从未发生。反过来，一个尚未得到确认的动作，也不应被轻率地标记为成功。

因此，Nova 把状态、事件和边界当作设计问题，而不是事后补上的界面细节。Web、终端和 CLI 都要能从同一套运行时理解当前任务，而不是各自保存一份容易分叉的故事。

## 从草案到验证

项目已经有设计评审稿和持续迭代的原型，但这离完整产品还有距离。设计说明的是目标；实现和回归场景才决定目标能否兑现。

这个博客会持续记录两者之间的差距：做了什么，为什么这样做，以及哪些地方还没有足够证据。想看 Nova 的整体介绍，可以从 [项目页](/nova/) 开始。
