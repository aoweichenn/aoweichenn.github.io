# 原型不等于产品

<PostMeta date="2026-10-27" :tags="['Nova', '开发日志']" />

项目有了界面、命令和可运行代码，就很容易把它称作“已经完成”。对 Nova 这样的 Agent 工作台，这种说法会遮住最关键的部分：失败后状态是否仍可信，工具效果是否被正确结算，不同客户端是否真的理解同一件事。

Nova 目前有 C++20 Host、TypeScript Web 和终端／CLI 的原型入口，也形成了较完整的目标设计。它们让继续开发有了基础，却不等于所有设计契约都已得到实现与验证。

## 三种不同的表述

**设计目标**描述想要保证什么。例如一次任务如何恢复、一个工具结果何时算确定，以及人做出的决定怎样进入运行记录。

**已有原型**说明某条路径能够工作，或者某组场景已有实现。它可能还依赖特定环境，也可能没有覆盖所有失败情况。

**完成验证**要求用明确的场景和回归证据说明边界成立。只有做到这一步，才能把能力当作可靠的交付承诺。

这也是本站的写法：介绍设计时标明它是方向，介绍进度时说明证据边界。想看目前的公开状态，可以直接访问 [Nova 进展](/progress/)。
